# 잇다 itda-ai 결정 기록
- 9/28 라벨 기준: "자다 깸"은 낮이라고 명시하지 않으면 야간 각성으로 봄. 깼다는 말 없이 밤에 한 다른 행동만 있으면 야간 각성을 추가하지 않음. "방에 누가 있다고 하심"은 환각(기획안 4-3 예시). 화내기·짜증만 있으면 과민·짜증.
- 9/28 데이터 정리: S3 눈 검사 틀림 7건, 야간 각성+낮에 계획 오류(S3-0244, W_test-0112, W_test-0279), 초조·공격/야간 각성 근거 불일치 15건을 학습·평가 세트에서 뺌. S4 눈 검사는 AI 보조 검토 후 위 기준으로 판정.
- 9/28 결과: train 1977 / val 200 / synth_eval 300. 유형별 사건 수 297~316, 빈 결과 비율 0.103.

- 서비스 모델 `itda-a` = `itda-gemma4-e4b:q4_k_m`. 백엔드는 지금처럼 `/api/chat` + `config/event_schema.json` 강제 + temperature 0으로 호출함
- 원본 gguf: `ml/train/out_gemma4_e4B/itda-gemma4-e4b-q4_k_m.gguf` (Git 밖 보관). Modelfile은 Ollama 베이스 모델(`gemma4:e4b-it-q4_K_M`)의 것을 FROM만 바꿔 씀
- 교체할 때는 `ollama cp <모델> itda-a` 한 줄로 바꾸고 settings.yaml은 건드리지 않음

파인튜닝 효과 (파인튜닝 전은 노트북 제로샷, 시스템 프롬프트만):
- Gemma 4 E4B: 0.8622 → 0.9920(노트북) / 0.9858(Ollama Q4_K_M)
- EXAONE 4.0 1.2B: 0.0875 → 0.9601(노트북) / 0.9628(Ollama raw)

### 선택 이유
1. 서비스 호출 조건(스키마 강제)에서 F1이 가장 높고, 스키마를 강제해도 강제하지 않을 때와 점수가 같음
2. Q8_0과 F1 차이는 0.003인데 크기는 5.3GB 대 8.0GB, CPU 최대 처리 시간은 20초 대 30초 → Q4_K_M
3. Qwen과의 차이(0.008)는 300건으로는 유의하다고 보기 어려움. 다만 Qwen은 스키마를 강제하면 필드 순서가 바뀌어 점수가 떨어짐
4. EXAONE은 가장 빠르지만 Ollama 0.34에서 `/api/chat`으로는 학습 조건이 재현되지 않고(raw 호출 필요), 라이선스가 비상업·연구용임

### 발견 사항
- Ollama 0.34.1은 gguf에 jinja 채팅 템플릿이 든 일부 모델(EXAONE)에서 Modelfile의 TEMPLATE을 무시하고 원래 템플릿으로 등록함. 이때 생각 모드가 기본으로 켜져 학습 때와 다른 프롬프트가 됨
- 스키마 강제(`format`에 JSON 스키마)를 하면 일부 모델(EXAONE, Qwen)에서 JSON 필드 순서가 알파벳순(count → evidence → status → time_expr → type)으로 강제됨. 학습 순서(type → status → time_expr → count → evidence)와 달라 성능이 떨어짐. Gemma 계열(3, 4)은 순서가 유지됨
- Gemma 4 E4B는 사건이 없는 잡담 메모 35건 중 2건에서 사건을 뽑음(빈 결과 정확 0.943). 나머지 모델은 1.0
- 긴 메모 실험(403자): 목록에 없는 행동("벽에 대변을 칠함")이 섞이면 근거와 유형의 짝이 한 칸씩 밀리는 오류가 있음. 사건 단위 채점으로는 1건 오류로만 보여 수작업 평가에서 근거-유형 짝을 따로 볼 필요가 있음. 다음 학습 때 시스템 프롬프트의 "목록 밖 관찰" 예시에 대변 관련 행동을 추가함

### 한계와 남은 일
- 모든 숫자는 합성 평가 세트 기준임. 학습 데이터와 같은 방식으로 만들어 점수가 부풀었을 수 있으므로 수작업 100건 평가가 필요함
- EXAONE의 CPU 처리 시간은 raw 호출로 다시 재야 함 (스키마 강제 조건 값 4.85초는 출력이 비정상이라 비교에 쓰지 않음)
- 모델 간 차이의 통계적 유의성(부트스트랩 신뢰구간)은 아직 계산하지 않음
- 결과 원본: `ml/eval/results/compare.md`, 모델별 `eval_*.json`
