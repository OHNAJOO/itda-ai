### 선택 이유
1. 서비스 호출 조건(스키마 강제)에서 F1이 가장 높고, 스키마를 강제해도 강제하지 않을 때와 점수가 같음
2. Q8_0과 F1 차이는 0.003인데 크기는 5.3GB 대 8.0GB, CPU 최대 처리 시간은 20초 대 30초 → Q4_K_M
3. Qwen과의 차이(0.008)는 300건으로는 유의하다고 보기 어려움. 다만 Qwen은 스키마를 강제하면 필드 순서가 바뀌어 점수가 떨어짐
4. EXAONE은 가장 빠르지만 Ollama 0.34에서 `/api/chat`으로는 학습 조건이 재현되지 않고(raw 호출 필요), 라이선스가 비상업·연구용임

### 발견 사항
- Ollama 0.34.1은 gguf에 jinja 채팅 템플릿이 든 일부 모델(EXAONE)에서 Modelfile의 TEMPLATE을 무시하고 원래 템플릿으로 등록함. 이때 생각 모드가 기본으로 켜져 학습 때와 다른 프롬프트가 됨
- 스키마 강제(`format`에 JSON 스키마)를 하면 일부 모델(EXAONE, Qwen)에서 JSON 필드 순서가 알파벳순(count → evidence → status → time_expr → type)으로 강제됨. 학습 순서(type → status → time_expr → count → evidence)와 달라 성능이 떨어짐. Gemma 계열(3, 4)은 순서가 유지됨
- Gemma 4 E4B는 사건이 없는 잡담 메모 35건 중 2건에서 사건을 뽑음(빈 결과 정확 0.943). 나머지 모델은 1.0
- 긴 메모 실험(403자): 목록에 없는 행동("벽에 대변을 칠함")이 섞이면 근거와 유형의 짝이 한 칸씩 밀리는 오류가 있음. 사건 단위 채점으로는 1건 오류로만 보여 근거-유형 짝을 따로 확인할 필요가 있음. 다음 학습 때 시스템 프롬프트의 "목록 밖 관찰" 예시에 대변 관련 행동을 추가함
